# Подготовка к запуску

## Что работает сейчас

Вход по почте с одноразовым кодом, 14 направлений, сохранение ответов, серверный таймер, загрузка и вставка фотографий, автоматическая проверка кратких ответов, разбор, профиль и скидка на повтор. Внешние адаптеры ЮKassa и OpenAI подключены в коде, но реальные платежи, письма и качество ИИ без учётных данных не проверялись.

Текущий банк учебный. Математика содержит 25 авторских заданий, остальные предметы — по 4. Полноценные иностранные языки требуют аудирования и устной части, русский язык — изложения, отдельные предметы — практических материалов. Эти форматы ещё не реализованы. Эта версия пригодна для демонстрации сценария, а не для платного запуска по всем требованиям ТЗ.

## Подключение инфраструктуры

1. Установите Node.js 22.17+ и PostgreSQL. Создайте отдельную базу и пользователя с доступом только к ней. Схема `probnik_records` создаётся автоматически.
2. Выполните `npm ci`, скопируйте `.env.example` в `.env`, заполните `DATABASE_URL`, SMTP и `MAIL_FROM`.
3. Укажите публичный `APP_URL` с HTTPS, `DEMO_MODE=false`, `HOST=127.0.0.1`. При TLS к базе задайте `DATABASE_SSL=true` и настройте доверенный сертификат.
4. Запустите `npm start` через менеджер процессов. Поставьте HTTPS reverse proxy перед портом 3000. Для тела запроса разрешите 12 МБ. Не кешируйте `/api/`.
5. Добавьте ключи ЮKassa и OpenAI в окружение сервера. Не передавайте секреты в клиент, Git или чат. Модель должна поддерживать изображения и структурированный JSON Schema. Локальный деморежим никогда не вызывает внешнюю модель.

Альтернатива: `docker build -t probnik-ai .`, затем `docker run --env-file .env -p 127.0.0.1:3000:3000 probnik-ai`. В контейнере используется `HOST=0.0.0.0` и только рабочий режим. Если `.env` содержит `HOST`, уберите его для контейнера. PostgreSQL и SMTP должны быть доступны из контейнера по сетевым адресам, а не через его `localhost`.

Контейнер работает без root. Docker-сборка подготовлена, но на текущем компьютере не проверена.

## Проверка банка и оценивания

До приёма денег замените учебные банки в `server/bank.js` проверенными вариантами для нужного года. Для каждого задания нужны текст, правильные ответы, решение, тема, максимальный балл и критерии развёрнутого ответа. При обновлении варианта меняйте `version`. Снимок оплаченного варианта сохраняется в заказе и попытке; последующая правка банка не меняет старый результат.

Для полноценных предметов настройте шкалы в `server/grading.js`. Сейчас официальная рекомендованная шкала реализована только для математики 2026 года, остальные используют явно отмеченную учебную шкалу. Не выставляйте `demo: false` и `BANK_APPROVED=true`, пока банк и шкалы не утверждены предметными экспертами.

Прогоните известные экспертные работы через ИИ и сравните баллы по каждому критерию. Неоднозначные ответы отмечаются `review`; предполагаемые баллы хранятся отдельно и не входят в подтверждённую сумму. Административная панель для ручной перепроверки пока не реализована.

## Проверка интеграций

- SMTP: доставка кода, срок 10 минут, лимит 5 попыток и повторная отправка через минуту.
- ЮKassa: тестовый магазин, успешная и отменённая оплата, повтор запроса, возврат без оплаты, чек и скидка 25%. Выдача доступа происходит только после серверного запроса к провайдеру и проверки суммы, валюты и метаданных.
- OpenAI: текст, читаемое и нечитаемое фото, неверный JSON, недоступность API, низкая уверенность. Модель не должна следовать инструкциям внутри ответа ученика.
- PostgreSQL: `TEST_DATABASE_URL=...` и `npm test`. В GitHub Actions база поднимается автоматически; локально этот тест пропускается, если адрес тестовой базы не задан.

## Ограничения и эксплуатация

Хранилище PostgreSQL использует JSONB-записи и блокировку транзакций. Для небольшого MVP это обеспечивает целостность, но каждая транзакция читает набор записей целиком. Перед масштабированием нужны нормализованные таблицы, индексы по владельцу, выборочные запросы, отдельное защищённое объектное хранилище фото и очередь заданий. Текущая очередь рассчитана на один экземпляр приложения; горизонтальное масштабирование не поддерживается.

Лимиты входа хранятся в памяти процесса и считаются по сетевому адресу соединения. За reverse proxy все пользователи могут иметь один адрес: до публичного запуска перенесите лимиты на доверенный прокси или в общее хранилище. Не доверяйте произвольному `X-Forwarded-For` от клиента.

Резервируйте PostgreSQL и проверяйте восстановление. Фото доступны только владельцу аккаунта и передаются через авторизованные API. Настройте шифрование дисков и резервных копий, срок хранения, удаление данных и журнал действий оператора. Секреты хранятся только на сервере, cookie — HttpOnly/SameSite, запросы изменения состояния проверяют Origin.

До публичной регистрации и приёма платежей замените демонстрационные страницы условий и обработки данных утверждёнными документами оператора с контактами, сроками хранения и правилами возврата. Убедитесь в праве на веб-использование предоставленного шрифта.
